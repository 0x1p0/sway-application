# Sway 1.0.13

## Clean-runner release packaging

- Packaging now creates its own `build` directory before allocating temporary staging folders. It no longer depends on files left by a previous build job.
- Both workflows test packaging from a fresh checkout with no build directory, including archive rejection, version checks, missing release notes, and protection against overwriting existing outputs.
- App signing and packaging remain on separate runners. No signing keys or build caches are needed by the packaging job.

The 1.0.12 run passed Checks and app signing, then stopped at the missing packaging directory. No release was published. This version carries forward the same persistent app-signing certificate, update-signing key, permission-recovery help, and release safeguards; existing tags are not moved.

## Accessibility permission

**Upgrading from 1.0.10 or earlier may need one final permission grant.** If Sway appears enabled but gestures do not work, remove its old entry from System Settings → Privacy & Security → Accessibility, add `/Applications/Sway.app`, enable it, and choose **Check again** in Sway. Quit and reopen once if macOS still reports the old state.

Releases now use a persistent certificate-bound identity instead of a different ad-hoc identity on every build. Signature tests confirm two different builds share that identity; end-to-end Accessibility retention still requires an installed two-version test. Sway never resets or grants permissions automatically.

The app remains self-signed, **not Developer ID signed or notarized**. The first-install warning remains. Both release approvals, signed updates, and ZIP/DMG verification remain required.
