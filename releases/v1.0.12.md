# Sway 1.0.12

## Reliable release signing

- Explicitly register and unlock the temporary signing Keychain on the build runner instead of relying on implicit registration.
- Restore the original Keychain search list and remove the temporary identity after signing, including error paths. Default Keychain and certificate trust settings are unchanged.
- Report credential-free error categories and test signing in its own workflow step, so signing failures are easier to diagnose.
- Add regression coverage for fresh runner setup, signing failures, interrupted signing, cleanup, and secret-safe diagnostics.

The 1.0.11 workflow stopped before publication. This release carries forward its persistent app-signing identity and permission-recovery help, using the same public certificate and private signing keys. Existing tags are not moved.

## Accessibility permission

Earlier releases used ad-hoc signatures that changed identity with each build. Releases now pin the same certificate and bundle identifier. **Upgrading from 1.0.10 or earlier may need one final permission grant:** remove the old Sway entry from System Settings → Privacy & Security → Accessibility, add `/Applications/Sway.app`, enable it, and choose **Check again** in Sway. Quit and reopen once if macOS still reports stale permission state.

Two different universal test builds verify against the same identity after their temporary Keychains are removed. End-to-end permission retention still requires an installed two-version test; Sway never resets or grants permissions automatically.

Building, app signing, packaging, and update signing remain isolated. Both release approvals, pinned-certificate verification, ZIP/DMG comparison, and signed updates remain required. The app is self-signed, **not Developer ID signed or notarized**; the first-install warning remains.
